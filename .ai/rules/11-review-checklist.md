# Checklist de Revisão

## Objetivo

Este documento define os critérios mínimos de qualidade para qualquer capítulo do curso.

Antes de considerar um capítulo concluído, revise todos os itens abaixo.

Caso alguma resposta seja negativa, o capítulo deve ser ajustado.

---

# 1. Contexto

- [ ] O capítulo deixa claro em que momento da evolução do sistema estamos?
- [ ] O aluno entende o que já foi construído?
- [ ] O novo problema foi apresentado antes da solução?
- [ ] Existe uma motivação clara para estudar o conteúdo?

---

# 2. Continuidade

- [ ] O capítulo mantém a história da empresa?
- [ ] O sistema continua evoluindo naturalmente?
- [ ] O código aproveita o que já foi desenvolvido anteriormente?
- [ ] Não há mudanças arbitrárias na modelagem?

---

# 3. Organização

- [ ] O capítulo possui uma introdução?
- [ ] A ordem dos assuntos é natural?
- [ ] A teoria aparece somente quando necessária?
- [ ] Existe uma conclusão?

---

# 4. Código

- [ ] Todo trecho de código possui uma justificativa?
- [ ] O código é apresentado gradualmente?
- [ ] O código é consistente com os capítulos anteriores?
- [ ] Não existem exemplos artificiais apenas para demonstrar sintaxe?

---

# 5. Programação Orientada a Objetos

- [ ] O conceito de POO apresentado resolve um problema real?
- [ ] As responsabilidades das classes estão bem distribuídas?
- [ ] Existe preocupação com coesão?
- [ ] Existe preocupação com baixo acoplamento?
- [ ] As decisões de modelagem foram justificadas?

---

# 6. Engenharia de Software

- [ ] O capítulo ensina o aluno a tomar decisões?
- [ ] Existem alternativas discutidas?
- [ ] As vantagens e limitações da solução aparecem?
- [ ] O aluno entende por que essa solução foi escolhida?

---

# 7. Linguagem

- [ ] O texto está claro?
- [ ] Existem frases excessivamente longas?
- [ ] O capítulo evita excesso de formalismo?
- [ ] O texto parece uma conversa técnica, e não um artigo científico?

---

# 8. Storytelling

- [ ] Existe uma pequena contextualização da empresa?
- [ ] O novo requisito surgiu naturalmente?
- [ ] A narrativa apoia o conteúdo técnico sem desviar o foco?

---

# 9. Exercícios

- [ ] Existe pelo menos um exercício?
- [ ] O exercício exige raciocínio, e não apenas copiar código?
- [ ] Sempre que possível, existe um exercício equivalente utilizando o sistema financeiro?

---

# 10. Encerramento

- [ ] O capítulo resume o que foi construído?
- [ ] O aluno consegue perceber sua evolução?
- [ ] Existe um gancho para o próximo capítulo?

---

# Erros que devem ser evitados

Evite os seguintes problemas durante a revisão:

- Introduzir teoria antes de existir um problema.
- Criar exemplos isolados que nunca mais serão utilizados.
- Reescrever completamente o código quando uma refatoração seria suficiente.
- Explicar apenas "como fazer", sem explicar "por que fazer".
- Utilizar exemplos irreais apenas para demonstrar um padrão de projeto.
- Apresentar conceitos muito abstratos sem aplicação prática.
- Introduzir muitos conceitos novos em um único capítulo.
- Utilizar nomenclaturas diferentes para o mesmo conceito.
- Quebrar a continuidade da evolução do sistema.

---

# Critério de aprovação

Um capítulo é considerado pronto quando:

- ensina um conceito;
- resolve um problema real;
- melhora o sistema desenvolvido até aquele momento;
- prepara naturalmente o próximo capítulo.

O aluno deve terminar a leitura com a sensação de que o projeto evoluiu e que o conhecimento adquirido será necessário para os próximos módulos.
